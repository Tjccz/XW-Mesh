# 湘网组网 · 4 周 MVP 计划

> 原则：**先跑通一条闭环，再谈功能。** 每周结束必须有一个能被别人验证的结果。

## 第 1 周｜节点接入链路（地基）

**目标**：不写任何界面，先用脚本把"陌生机器 → 网络节点"这条链路打通。

具体动作：
1. 准备一台干净的 Linux 机器（或虚拟机）作试验节点
2. 写 `scripts/join-node.sh`：下载官方 core → 写入配置 → 注册 systemd 服务 → 启动
3. 用你软路由上现有的自建控制台做对端，两边互 ping 验证

**验收标准**：在全新机器上执行一条命令，另一台机器能 ping 通它的虚拟 IP。
**交付物**：`scripts/join-node.sh` + 一份"最短接入步骤"记录。

> 这一步跑通了，产品就等于有了一半——因为"能接入"是所有管理功能的前提。

## 第 2 周｜控制台骨架

**目标**：把第 1 周的黑盒操作搬到网页上。

具体动作：
1. 建前后端工程（技术栈见 ARCHITECTURE.md）
2. 实现最小三件套页面：**登录 / 网络列表 / 节点列表**
3. 后端对接节点状态：定时拉取 `easytier-cli peer`，落库供前端展示

**验收标准**：网页上能看到"哪个节点在线、什么时候最后上报、虚拟 IP 是多少"。
**交付物**：可运行的本地控制台（`docker compose up` 即可起）。

## 第 3 周｜节点纳管闭环

**目标**：从"看"升级到"管"。

具体动作：
1. 网页上新增/修改网络参数 → 推送到节点 → 节点自动生效并重启 core
2. 每次变更落一条 `node_config` 快照 + `audit_log`
3. 提供"回滚到上一次可用配置"按钮

**验收标准**：网页改一次虚拟网段，节点自动应用，另一个节点无需人工干预即可通信；改错了能一键还原。
**交付物**：可交付给同事试用的内测版本。

> `node_config` 快照 + 回滚是差异化点之一：组网出问题时，多数工具让你自己翻日志，我们让你看到"改了什么、退回哪一版"。

## 第 4 周｜真实场景验证 + 品牌化

**目标**：拿一个真实场地跑起来，而不是停留在实验环境。

具体动作：
1. 选一个真实场景（自有场地之间的互联、或一个愿意试用的客户）
2. 走完完整流程：注册 → 建网络 → 接入设备 → 远程访问 → 出问题排查
3. 补齐对外材料：产品名「湘网组网」、域名、落地页、使用文档

**验收标准**：用户（哪怕就是你自己）在**不看文档**的情况下能完成一次接入。
**交付物**：一个真实可用的最小产品。

## 并行事项（不占研发工时，但别拖）

- [ ] 商标查询与注册「湘网组网」（第 9 类 / 第 42 类）
- [ ] 对外提供服务前，评估增值电信业务相关资质
- [ ] 整理 EasyTier 的 LICENSE 与声明文本，纳入交付物

## 明确不做（MVP 阶段砍掉）

| 不做 | 原因 |
|---|---|
| 中继节点 | 带宽成本是真金白银，没有付费用户前不做 |
| 计费 / 套餐 / 支付 | 还没有用户，谈钱太早 |
| 多租户 / 组织架构 | 单租户跑通再说 |
| 自研客户端 App / GUI | 上游已有，重复造没有意义 |
| 修改 EasyTier 源码 | 触发 LGPL 义务，且无必要 |
| ACL / 审计的完整体系 | 第 3 周的 audit_log 先做最小版，别一上来就做大而全 |

## 第一个里程碑判断标准

跑完 4 周后，用一句话回答：

> **"我能不能在 10 分钟内，把一台从没碰过的新机器，接入到我朋友场地的那张网里？"**

答案是"能，而且不用我在旁边指导"——这个产品就立住了。答不上来，说明方向偏了，先修这条链路，别加新功能。
